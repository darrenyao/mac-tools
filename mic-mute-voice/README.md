# MicMuteVoice：用麦克风的静音键开关语音输入法

按一下麦克风上的静音键，语音输入法就开始听写；再按一下，听写就停止。不用碰键盘。

我自己的搭配是**绿联 CM770 双模桌面麦克风**加**豆包输入法**（macOS）。只要你的麦克风满足下面说的一个条件，换成别的麦克风和输入法也能用。

```
取消静音 → 输入法没在听 → 程序替你按一下右 Option → 开始听写
按下静音 → 输入法正在听 → 程序替你再按一下右 Option → 停止听写
```

---

## 为什么要绕一圈

最直接的想法，是把麦克风按钮改成一个快捷键。我试了，这条路走不通。

**按钮不给电脑发任何信号。**我用 macOS 的 IOKit 接口写了一个监听程序，盯着麦克风接收器上报的所有按键。然后单击、双击、长按，无线模式和插线模式各试了一遍，一条按键记录都没有。其实接收器向系统申报过一组媒体键（音量加减、静音、播放/暂停），只是按钮根本没用上它们。静音是在麦克风内部完成的，电脑并不知道你按了按钮。绿联官网上也找不到这款麦克风的固件升级或配套软件。

所以 Karabiner-Elements、BetterTouchTool 这类改键工具在这里都用不上：它们只能改电脑收得到的按键。

**但静音时，麦克风传来的声音是"纯 0"。**我让麦克风录了 82 秒，中间切换了几次静音，然后按每 0.1 秒切一段来统计：

| 状态 | 这 0.1 秒里值为 0 的采样点占多少 | 最大音量值（满量程 32767） |
|---|---|---|
| 静音（3 段，每段约 7 秒） | 每一段都是 100% | 0 |
| 没静音，也没人说话 | 最高 32%，没有一段到 100% | 最小也有 6 |

没静音时，哪怕房间里一点声音都没有，也会有一点底噪；静音时，数据是绝对的 0。所以程序只要看到"连续 0.3 秒全是 0"，就能判定你刚按了静音；一出现非 0 的数据，就判定你取消了静音。

## 怎么保证开关不会反过来

如果每次切换静音都无脑按一下快捷键，一旦你中途用键盘关掉了输入法（或者输入法因为没人说话自己停了），后面每次按按钮，效果都会反过来。

所以程序在按快捷键之前，会先查一下输入法**此刻是不是正在用麦克风**。macOS 14.2 之后，CoreAudio 可以列出每个进程是否正在录音（`kAudioHardwarePropertyProcessObjectList` 和 `kAudioProcessPropertyIsRunningInput` 这两个接口）。豆包听写时，它的进程 `com.bytedance.inputmethod.doubaoime` 会出现在"正在录音"的名单里；停止后马上消失。规则是：

- 取消静音时，输入法**没在听**才按
- 按下静音时，输入法**正在听**才按

## 开会时不会误触发

腾讯会议、飞书、钉钉、企业微信、微信、Zoom、Teams 里任何一个正在用麦克风，程序就认为你在开会或通话，这时切换静音不会动输入法。判断方法和上面一样，看这些程序是不是正在录音，而不是看哪个窗口在最前面。开会时你切去别的窗口，判断也不会出错。

## 安装

要求：macOS 14.2 或更新，装有 Xcode 命令行工具（能运行 `swiftc`）。

```bash
git clone https://github.com/darrenyao/mac-tools.git
cd mac-tools/mic-mute-voice
./install.sh
```

装好后要做两件事：

1. 弹出"MicMuteVoice 想访问麦克风"时，点**允许**。
2. 打开**系统设置 → 隐私与安全性 → 辅助功能**，把 **MicMuteVoice** 打开（程序要用这个权限模拟按键）。然后运行 `./restart.sh`。

之后它会在每次登录时自动运行，崩溃了也会被系统自动拉起。

## 配置

配置文件在 `~/.config/mic-mute-voice/config.json`，改完运行 `./restart.sh` 生效，不用重新编译。

| 配置项 | 默认值 | 说明 |
|---|---|---|
| `devicePrefix` | `UGREEN MIC-CM770` | 麦克风名称的开头部分。无线和插线模式下设备名不同，用开头部分就能同时匹配 |
| `toggleKey` | `right_option` | 输入法的听写开关键，可选 `right_option` / `right_command` / `right_control` / `right_shift` |
| `imeBundleIDs` | 豆包输入法 | 输入法的进程标识，用来判断它是不是正在听 |
| `meetingBundleIDs` | 常见会议软件 | 这些程序在用麦克风时，程序不动作 |
| `tapEnabled` | `true` | 改成 `false` 就只写日志、不按键，调试时用 |
| `zeroRunSeconds` | `0.3` | 连续多少秒全是 0 才算静音 |
| `unmuteMinNonzero` | `20` | 一段音频里至少出现多少个非 0 采样才算取消静音 |
| `warmupSeconds` | `1.0` | 刚开始录音时忽略的时长，因为录音启动时常有一小段 0 |

你的麦克风名称，可以在 系统设置 → 声音 → 输入 里看。进程标识可以用 `osascript -e 'id of app "应用名"'` 查。

## 日志

`~/Library/Logs/MicMuteVoice.log`，每次切换都会记一行，比如：

```
麦克风 → 未静音｜正在用麦克风的程序：无｜按 right_option → 开始语音
麦克风 → 静音｜正在用麦克风的程序：com.bytedance.inputmethod.doubaoime｜按 right_option → 停止语音
```

## 卸载

```bash
./uninstall.sh
```

它会删掉程序、登录启动项、配置、日志和权限记录，源码目录保留。

## 我的麦克风能用吗？

关键就一条：**静音时，麦克风传给电脑的是不是纯 0。**有的麦克风静音时只是把音量压得很低，那就不行。

检查方法（需要 `ffmpeg`，可以用 `brew install ffmpeg` 安装）：

```bash
# 列出音频设备，记下你的麦克风编号，比如 [1]
ffmpeg -f avfoundation -list_devices true -i "" 2>&1 | grep -A10 "audio devices"

# 先把麦克风设成静音，录 3 秒（":1" 换成你的编号）
ffmpeg -loglevel error -y -f avfoundation -i ":1" -t 3 -ac 1 -ar 16000 -f s16le /tmp/muted.raw
python3 -c "import array; a=array.array('h',open('/tmp/muted.raw','rb').read()); print('非 0 采样数：', sum(1 for x in a if x))"
```

静音时输出"非 0 采样数：0"，就能用。然后取消静音、保持安静，再录一次，这次的数应该明显大于 0。

## 已知限制

- 程序一直开着麦克风，屏幕右上角的橙色麦克风小点会常亮。拔掉麦克风后，程序不会去用别的麦克风，小点也就灭了。
- 实测插着麦克风时，平均占一个 CPU 核心的 2.5% 左右。
- 程序只监听配置里那个麦克风，但输入法用的是系统默认输入设备。如果把默认输入换成别的麦克风，按钮照样能开关输入法，只是输入法会用另一个麦克风听。
- 程序用的是本地临时签名（ad-hoc），每次重新编译后，系统都会忘掉之前给过的麦克风和辅助功能权限，需要重新授权。只改配置不需要重新编译。
